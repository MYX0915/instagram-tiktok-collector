# TikTok 响应字段与采集规则

## 1. 采集范围与运行方式

使用 Playwright 和系统 Google Chrome，加载本地 `account/tiktok.cookies.json`。进入主页前注册响应监听，直接读取目标作者的首批普通作品自然响应，不再次请求首批；后续未取得的数据在 TikTok 同源网页中通过 `fetch` 请求。输出使用中文字段，保存到 `data/tiktok/`。不依赖模拟点击或滚动，不在代码、文档或输出日志中保存固定会话令牌。

采集范围包括作者公开资料、普通作品信息、互动量、播放量、评论和回复。评论者与回复者只保存评论接口返回的用户摘要，不额外请求其详情接口或主页。`tiktok.py` 默认不限制作品数量，按普通作品列表返回顺序持续分页至 `hasMore=false`，按作品 ID 去重并包含置顶；可用 `--limit` 手动限制数量，每个作品独立保存为 `data/tiktok/<用户名>/<作品ID>.json`，账号清单保存为同目录的 `index.json`。

代码已实现作者主页解析、普通作品分页、评论及回复分页与关联、评论区用户摘要保存，单作品信息取自已确认的普通作品列表，不额外调用尚未确认的单作品详情接口。公共参数仅从已支持的数据接口在当前会话内提取，并按接口保留；应用身份参数使用已确认的网页配置，避免其他接口覆盖。不保存或硬编码抓包中的签名、Cookie、msToken；请求依赖当前站点正常浏览器行为，不实现签名算法或验证绕过。

目标账号保存在项目 `targets.json` 的 `tiktok` 节点中，保留 Snidin、DCXC、AVEYA 分组。

### 临时请求失败与重试

普通主动接口请求发生网络传输错误、超时、HTTP 200 空正文或 HTTP 429/500/502/503/504 时，等待 5 秒自动重试当前请求一次；响应包含更长的 `Retry-After` 时按该时间等待。请求参数与目标保持不变，不循环重试。仍失败时转入原有人工暂停或停止流程；人工确认后最多再请求一次。

HTTP 401/403、业务失败（含状态码 5）、响应格式或目标身份错误不自动重试。主页自然捕获的首批作品响应不主动重放；回复游标对照诊断仍只发起一次请求。成功重试只说明该请求恢复，不据此判定此前失败一定由限流或验证码引起。

## 2. 请求与响应分类

| 请求路径 | 数据类型 | 处理方式 |
|---|---|---|
| `/@用户名` | 作者主页 HTML，内嵌作者资料及统计 | 提取目标作者资料 |
| `/api/user/detail/` | 单用户资料与统计 | 仅保留样本说明；当前采集流程不调用 |
| `/api/post/item_list/` | 作者普通作品列表，支持游标分页 | 按目标作者匹配，提取作品、播放量和互动计数 |
| `/api/repost/item_list/` | 目标用户再发布的作品列表 | 与原创作品分别归类，条目的作者可能为其他用户 |
| `/api/story/item_list/` | Story 内容列表 | 与普通作品列表区分，不当成作者全部作品 |
| `/api/user/list/` | 当前样本为账号推荐列表，包含 `userRecommendInfo` | 不当成目标作者资料或目标作者作品列表 |

接口名称和含义以已提供样本为依据。后续响应仍需按目标用户及内容类型核对，不仅凭页面 Referer 或接口路径判断归属。

## 3. 作者主页 HTML

### 3.1 请求与解析位置

作者主页地址格式：

```text
https://www.tiktok.com/@用户名
```

在 HTML 中找到以下脚本元素，读取文本后使用 JSON 解析器解析，不执行文本：

```html
<script id="__UNIVERSAL_DATA_FOR_REHYDRATION__" type="application/json">
```

作者数据路径：

```javascript
data.__DEFAULT_SCOPE__["webapp.user-detail"].userInfo
```

结构：

```text
userInfo
├── user       作者资料
├── stats      作者统计
├── statsV2    另一组统计表示
└── itemList   内容列表字段，允许为空
```

提取时核对 `user.uniqueId` 与目标用户名，以及可取得的用户 ID。缺少节点、返回非目标账号或页面不可访问时，不把空结果解释为作者无资料。

### 3.2 作者资料字段

下表字段路径相对于 `userInfo`。

| 中文输出字段 | 原字段 | 说明 |
|---|---|---|
| 用户ID | `user.id` | 保留为字符串，不转换为 JavaScript Number |
| 用户名 | `user.uniqueId` | 作者主页路径中的账号名 |
| 昵称 | `user.nickname` | 作者显示名称 |
| 简介 | `user.signature` | 保留原文与换行 |
| 大头像地址 | `user.avatarLarger` | 原样保存资源地址 |
| 中头像地址 | `user.avatarMedium` | 原样保存资源地址 |
| 小头像地址 | `user.avatarThumb` | 原样保存资源地址 |
| 是否认证 | `user.verified` | 布尔值 |
| 是否私密账号 | `user.privateAccount` | 布尔值 |
| 用户secUid | `user.secUid` | 核对后续用户相关请求的标识，不代替作品 ID |
| 账号创建时间字段 | `user.createTime` | 原始时间字段，当前未核验值及时间单位 |

### 3.3 作者统计字段

| 中文输出字段 | 原字段 | 说明 |
|---|---|---|
| 粉丝数 | `stats.followerCount` | 作者粉丝计数 |
| 关注数 | `stats.followingCount` | 作者关注计数 |
| 获赞计数 | `stats.heartCount` | 作者获赞统计，不是单作品点赞数 |
| heart原始计数 | `stats.heart` | 与 `heartCount` 分别保留，不相加 |
| 视频数 | `stats.videoCount` | 账号统计中的视频计数，不等于已采集作品条数 |
| digg原始计数 | `stats.diggCount` | 保留原始值，当前未验证其展示含义 |
| 好友计数 | `stats.friendCount` | 接口原始计数，具体展示含义待核对 |

`statsV2` 作为独立统计表示保留或核对，不与 `stats` 相加。缺失值与零值分别处理，不把未返回的数据填成零。

### 3.4 单用户详情接口

请求路径为 `/api/user/detail/`，当前样本通过 `uniqueId` 指定用户名，同时携带空字符串 `secUid`。该样本确认按用户名查询，尚未确认仅传数字用户 ID 或仅传 `secUid` 的请求方式。

响应的 `userInfo` 位于 JSON 根节点，其 `user`、`stats`、`statsV2` 复用本节作者资料及统计映射，不需要从 HTML 脚本提取。

当前采集流程不调用此接口，也不请求评论者或回复者主页。仅保存评论接口返回的用户摘要；粉丝数、简介等未返回字段不再补充，不参与完成状态判断。作品作者仍从目标主页内嵌资料读取。接口结构与历史验证样本保留在附录中，不代表当前程序启用资料补充。

## 4. Story 列表

请求路径为 `/api/story/item_list/`，当前样本携带 `authorId`、`count`、`cursor` 等业务参数。

响应的内容列表为 `itemList[]`，每条包含：

- `id`：内容数字 ID，按字符串保存。
- `author`：发布者资料。
- `authorStats`、`authorStatsV2`：发布者统计。
- `desc`：内容文案。
- `createTime`：发布时间字段，单位待结合样本值核对。
- `video`：视频资源信息。
- `stats`、`statsV2`：内容统计。
- `story`：Story 相关信息。

当前统计字段包括 `diggCount`、`commentCount`、`playCount`、`shareCount`、`collectCount`，分别记录点赞、评论、播放、分享、收藏计数，不代替普通作品采集结果。

响应同时提供 `HasMoreAfter`、`HasMoreBefore`、`MaxCursor`、`MinCursor` 等字段。当前未验证后续分页请求和游标传递规则，不将这些参数直接套用到普通作品、评论或回复列表。

## 5. 推荐账号列表

当前 `/api/user/list/` 样本包含请求参数 `scene`、`targetUserId`、`count`、`maxCursor`、`minCursor` 等。

响应数据位于 `userList[]`，条目包含 `user`、`stats`、`statsV2` 和 `userRecommendInfo`。这些用户不等于目标作者，不用于覆盖目标作者资料，也不是作者作品列表。

## 6. 普通作品列表与分页

### 6.1 请求参数

请求路径为 `/api/post/item_list/`。首批样本使用 `cursor: 0`，后续页使用上一批响应返回的游标。

| 参数 | 含义与处理方式 |
|---|---|
| `secUid` | 目标作者标识，与主页 `user.secUid` 核对 |
| `cursor` | 作品列表游标，按原始字符串保存，不自行增减或用作品 ID 替代 |
| `count` | 请求条数，不保证每批响应数量始终相同 |
| `from_page` | 当前样本为 `user` |
| `post_item_list_request_type` | 当前样本为 `0`，不推测其他值含义 |
| `coverFormat` | 当前样本为 `2`，保留原参数语义，不凭此推断内容类型 |
| `needPinnedItemIds` | 后续页样本为 `true`；首批样本未携带此参数，不强制认为所有请求都必须携带 |

### 6.2 响应字段

| 数据 | 字段路径 | 说明 |
|---|---|---|
| 作品列表 | `itemList[]` | 普通作品条目，不与 Story 列表混用 |
| 下一批游标 | `cursor` | 后续请求的游标来源，保留原值 |
| 是否还有后续批次 | `hasMore` | 结束状态，不以返回条目不足请求数量代替 |
| 业务状态 | `statusCode`、`status_code`、`status_msg` | 核对响应是否成功；当前样本两个状态码均为零 |
| 作品ID | `itemList[].id` | 按字符串保存，用于合并去重 |
| 是否置顶 | `itemList[].isPinnedItem` | 首批样本前 3 条为 `true`，缺失时不推断为明确返回 `false` |
| 作者 | `itemList[].author` | 核对用户 ID、用户名和可取得的 `secUid` |
| 作者统计 | `itemList[].authorStats`、`authorStatsV2` | 作者统计，不是该作品互动统计 |
| 作品文案 | `itemList[].desc` | 原文保留 |
| 作品发布时间 | `itemList[].createTime` | 当前样本为 Unix 秒级时间戳 |
| 点赞数 | `itemList[].stats.diggCount` | 单作品点赞计数 |
| 评论数 | `itemList[].stats.commentCount` | 不代表已取得评论正文 |
| 播放量 | `itemList[].stats.playCount` | 当前样本直接提供有效值 |
| 分享数 | `itemList[].stats.shareCount` | 与再发布数分别保存 |
| 收藏数 | `itemList[].stats.collectCount` | 单作品收藏计数 |
| 再发布数 | `itemList[].statsV2.repostCount` | 当前样本在 `statsV2` 中提供 |
| 视频信息 | `itemList[].video` | 当前首条包括封面、时长、宽高等，不保证带有视频播放地址 |
| 图文信息 | `itemList[].imagePost` | 存在时保留，不把全部普通作品强制当成视频 |

当前样本的 `stats` 计数为数字，`statsV2` 对应计数为字符串。两组数据不相加，保留来源与原类型，后续如需统一数字类型应显式转换。视频时长等单位仍需逐字段核对。

### 6.3 分页采集规则

1. 从作者主页资料取得目标用户 ID、用户名和 `secUid`。
2. 核对列表请求的目标作者参数及响应每条作品的发布者。
3. 按作品 ID 合并去重，保留实际抓到的统计与采集时间。
4. 后续页使用上一批响应的 `cursor`；不把它当作可自行计算的时间或作品 ID。
5. 默认不限制作品数量，`hasMore: true` 时继续请求，`hasMore: false` 时记录该列表分页结束。默认也不限制作品、评论和回复页数。显式指定 `--limit` 时可在达到数量上限后结束；显式指定 `--max-pages` 后，触及该分页上限仍为未完成。
6. 业务错误、空响应、重复游标、请求失败或中途停止不视为全量采集完成。

已核对首批及两个连续后续页，后续请求的 `cursor` 均与上一批响应一致。首批可以包含置顶作品，实际返回数量不保证等于 `count`；按作品 ID 去重，不以数量推断分页结束。浏览器内主动请求仍待验证。

### 6.4 再发布列表

`/api/repost/item_list/` 与 `/api/post/item_list/` 是不同列表。再发布请求的 `secUid` 指向再发布用户，但条目的 `author` 是作品原作者，不能将其他作者的作品标为目标用户原创。

如纳入采集，单独记录再发布关系，并与普通作品分别维护游标和完成状态。当前样本的再发布首批请求为 `cursor: 0`、`count: 30`，响应返回游标 `30`，不能将其分页规则与普通作品的游标混用。

## 7. 评论与回复

### 7.1 顶层评论请求与字段

请求路径为 `/api/comment/list/`。`aweme_id` 为作品数字 ID，`count` 为请求条数，`cursor` 为评论列表游标。作品归属以请求参数核对，不能仅凭 Referer 判断。

评论列表位于 `comments[]`。返回游标不等于取得的评论数量。以下字段以非空评论样本核对：

| 中文字段 | 原字段 | 说明 |
|---|---|---|
| 作品ID | `aweme_id` | 与请求目标作品 ID 匹配 |
| 评论ID | `cid` | 保留为字符串，按作品 ID 与评论 ID 去重 |
| 评论内容 | `text` | 保留正文 |
| 评论发布时间 | `create_time` | 当前样本为 Unix 秒级时间戳 |
| 评论点赞数 | `digg_count` | 不与作品点赞数混用 |
| 回复数 | `reply_comment_total` | 不等于当前已获取回复条数 |
| 父评论ID | `reply_id` | 顶层样本为字符串 `0`；回复中指向根评论 |
| 直接回复目标ID | `reply_to_reply_id` | 与根评论 ID 分别保存，字符串 `0` 不当成有效评论 ID |
| 预览回复 | `reply_comment[]` | 可能为 null、空列表或部分回复，不能自动视为完整 |
| 是否作者点赞 | `is_author_digged` | 布尔值 |
| 当前用户是否点赞 | `user_digged` | 保留接口原值 |
| 作者置顶标记 | `author_pin` | 保留接口原值 |
| 评论语言 | `comment_language` | 保留接口原值 |
| 图片列表 | `image_list` | 可能为 null，不假定所有评论只有文本 |

评论者位于 `user`，与作者主页的字段命名不同：

| 中文字段 | 评论 `user` 字段 | 对应主页字段 |
|---|---|---|
| 用户ID | `uid` | `user.id` |
| 用户名 | `unique_id` | `user.uniqueId` |
| 昵称 | `nickname` | `user.nickname` |
| 用户secUid | `sec_uid` | `user.secUid` |
| 头像信息 | `avatar_thumb` | `user.avatarThumb` 的结构需分别处理 |

当前评论者摘要没有提供简介、粉丝数等完整主页资料；不另行补充，不将缺失值填成零。

### 7.2 顶层评论分页

- 首批样本请求 `cursor: 0`、`count: 20`，响应返回 `cursor: 20`、`has_more: 1`。
- 后续页以响应游标作为请求 `cursor`，样本请求 `20` 后返回 `40`。
- `has_more: 1` 表示仍有后续页，`has_more: 0` 表示该响应不再指示后续页。
- 保留 `total` 原值，不将它直接视为已取得的顶层评论数量，也不要求其等于评论列表加回复的条数。
- 重复请求相同游标可能返回同一页；按 `cid` 去重，不能按请求次数累计评论量。
- `focus_state` 的变化不作为分页判断依据。

### 7.3 展开回复

请求路径为 `/api/comment/list/reply/`，与顶层评论的参数名不同：

| 请求参数 | 说明 |
|---|---|
| `item_id` | 回复所属作品 ID；顶层评论请求使用 `aweme_id` |
| `comment_id` | 被展开的根评论 ID |
| `cursor` | 回复列表自己的分页游标，不与顶层评论游标混用 |
| `count` | 展开请求使用 `3`，不等同于接口 `total` 或实际返回条数 |

回复也位于 `comments[]`，字段可复用评论字段映射。逐条核对 `aweme_id` 与目标作品、`reply_id` 与请求的根评论 ID；同时保存 `reply_to_reply_id`，以保留回复之间的直接关联。`reply_to_userid`、`reply_to_username`、`reply_to_nickname` 可作为被回复用户信息保存，不代替回复发布者的 `user`。

当回复页条目的 `cid` 等于当前请求的根评论 ID、`aweme_id` 与 `reply_id` 均等于当前作品 ID，且 `reply_to_reply_id` 为零值或缺失时，判定为当前根评论自身的回显，仅记录关联字段及请求游标，不将其加入子回复列表。该规则不适用于其他父评论不匹配的条目，不放宽实际子回复的作品和父评论校验。

将顶层响应中的 `reply_comment[]` 与展开接口返回的回复按 `cid` 合并去重。嵌套预览、回复数量、回复接口返回条数及 `total` 不保证相同，不能只依据某个数量声明完整。

展开回复的起始 `cursor` 统一为 `0`，不能根据预览回复数量计算偏移；预览不保证是展开列表的前缀。后续使用上一页响应的 `cursor`，不自行递增。预览已覆盖明确的回复计数时无需重复展开。保留预览和后续返回条目的评论时间、根评论 ID 与直接回复目标 ID。

`has_more: 0` 表示该次接口不再指示后续页。分页完成与数量一致性独立记录：请求成功且分页结束时，完成状态表示已保存当前接口返回的全部条目，不表示计数一定一致或取得历史全部回复。预览与展开结果按 ID 去重后，分别与根评论回复计数和展开接口 `total` 核对；差异保存为警告，不单独触发流程未完成。请求失败、分页未结束、游标异常或达到分页上限仍标记未完成，并保留原始失败原因，不将计数差异归类为验证码。

`回复采集状态` 包含 `回复分页是否完成`、`已采集回复数`、`顶层评论回复计数`、`回复接口总计数`、`数量是否一致`。未返回的计数保留 `null`。预览已覆盖计数而无需展开时记录结束依据。作品及索引保存差异标记，账号索引汇总差异作品数；存在警告不等同于请求失败。

## 8. 相关作品列表

请求路径为 `/api/related/item_list/`。请求中的 `itemID` 为关联作品标识，不能据此认定响应就是该作品详情。

响应 `itemList[]` 包含相关作品及其作者、发布时间、文案、视频信息与互动统计。按作品 `id` 核对归属，不把推荐列表第一条当成当前目标作品，不将该接口用于评论正文采集。
